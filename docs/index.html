Connection setup

While there is option to connect to pump directly from AAPS (B), I would like to remind you that t:mobi is pump without screen, and if something goes wrong, there is no way to fix the pump from AAPS. To solve serious problems with pump, you would either need offical app (on iPhone, there is still no app for Android) or controlX2. ControlX2 is small Android app (intended mainly for t:slim X2) which can monitor your pump, issue Bolus, TBR. Newer versions were extended with Mobi specific commands and requirements (change cartridge, fill cannula, etc), some of which we directly use in this driver, but what is important difference is, that it has ability to issue any supported command to pump directly, and ability to debug problems. Installing controlX2 doesn't mean that there will be both applications running, it just means that if something goes wrong, we can shutdown (force close) AAPS and then start controlX2 (both apps can't run at the same time, because they both require exclusive access to pump.
Once pump is configured and software is running, connection to pump is 24/7, we never disconnect from pump.

A.) Using shared connection with controlX2

Good. So you decided to go with with shared option. Visit https://github.com/jwoglom/controlX2/releases and search for latest version (1.0.0-20251102 at time of writing this documentation). This is currently only modified version that supports shared connection with AAPS. Install app on the same phone where you will be using AAPS. Pair your t:mobi with app and get it running. T:mobi pairing on Android is little temperamental, so you might need several tries. To pair the pump you need to put it on the pad, and then press the button for 3 seconds, which will put it into pairing mode. After your pump is succesfully communicating with controlX2, you need to go into Setings, then Debug and then "View Pump State". There will be json with all connection data, use option "Save to Clipboard". Force close the app and then start AAPS.

In AAPS select t:mobi driver and go to configuration. Enable "Use Shared Connection", which will make "Shared Connection Data" visible, click on the option and copy the value you got from controlX2 and exit configuration. AAPS should now be able to connect to your pump. If for some reason doesn't work, "Force Close" AAPS and restart. Driver should be able to connect to pump now.

Overview in T:MOBI tab

Once you have Mobi configured, tab T:MOBI becomes available, displaying all important information. Information is divided in 6 different sections.

Section 1: Information about your pump: Firmware, Serial Number and BT address. If you have configured display of driver version, then version of driver will also be displayed (when reporting bugs in driver, this information needs to be in report. It helps us pinpoint the problem, and we can also determine if this error was already fixed).

Section 2: : Displays State of pump connection, this shows Connected if pump is connected, or if command is running it will show name of command running and also the Queue of commands (queue hides when empty).

Section 3: Battery status, reservoir level and when last command was processed.

Section 4: Displays last bolus, base basal rate and if temp basal is currently running (and with what values).

Section 5: Displays driver errors (mostly this would be filled if there is problem with configuration or if for some reason we lost connection with the pump). At the moment driver is unable to reconnect automatically with pump (auto reconnect will be added in Phase 3). If you loose connection with pump please restart AAPS (with Force Stop)). If there are no error, this section is not visible. TODO

Section 6: Indicator for Pump Data Status. This shows 3 labels NOTIFICATION, EVENTS and HISTORY. If they are in natural color (depending on theme) then there is nothing to see, but if options colors, then there are new items available (red for new notifications, green for new events and blue for new history items).

Configuration options

 
Use Shared connection: See previous section (Connection setup) how this works. But in short we can either use shared connection for which we also need to populate Shared connection data, or we can use just AAPS connection, for which we need to click on Tandem Pump Pairing which will lead us through pairing process. Options become visible depending on the switch...

Max Bolus on Pump:  This sets what is max amount of bolus allowed. This is not limited to the current hour, its just max amount you can use at any time, value should be beween 1 and 25 (if you need bigger dose, you can just dose twice).

Max Basal on Pump:  This sets max amount of basal insulin person can receive in a hour. Valid values are 1 to 15. You can go with max value here, but if you want to limit this the formula is to look at your highest hourly value and then multiply it 2.5 (250% is max TBR possible).

Display driver version:  Display driver version on t:MOBI tab (in Section 1, 4th line if enabled - see Overview for more info)

Which Pump Events to Show?  We can either show all events, or just that ones that are AAPS Relevant.

How many Pump Events to Show?  We can limit how many Pump Events will be shown (15 items, Last 3/6/12/24 hours)

Show Cargo/Payload of Unknown Logs  If we select display of Unknown Logs, we can either display cargo/payload of Log entry, or not (cargo would be only in hexidecimal form each bit displayed).

Auto confirm Low Basal Delivery Alert  If low basal value is delivered (less than 50% ??), pump gives us special alerts. If enabled, such Alarms are automatically confirmed.

Quick Bolus  Button on pump can be configured to deliver Quick bolus. This option configures how much bolus can be delivered (0.5U, 1U, 2U, 5U, or cover for 2g, 5g, 10g, 15g of carbs).



Details how driver and mobi work

Startup sequence

Everytime you run AAPS and driver connects to the pump, there will be sequence of commands executed, that will retrive initial data and see if your pump is running ok and what the state it. This process can take up to 2 minutes, depending on how fast your phone is, how good BT connection is and if this is one of first times running the driver. On each start driver also checks if you have enabled internal mobi loop and disables it (official tandem loop and AAPS loop can't run at the same time).

List of commands that will be executed is:
  • Check if pump time is correct, if not set it
  • Get any running Alarms or Alerts
  • Get Status of the pump (running, suspended)
  • Get History (for first day or so running, 1000 of history items will be retrieved on startup and every 5 minutes on regular status check, afterwards only new history is retrieved), see History section for more info
  • Get Remaining insulin info
  • Get Battery Level
  • Get All Configurations and check everything is set correctly on the pump, if not settings on pump are updated (
  • Get Last Bolus
  • Get Basal Profile

    • During startup sequence buttons are disabled.

    (Pump) Notifications

    Since pump doesn't have screen it must show notifications differently. This is done through beeps and/or vibrations and blinking of lights beside button. Also when notification happen, it can send event (not always) and/or certain alarm/alert setting is triggered. Driver reads this information every 5 minutes and if there are any notification, indicator is colored (see Overview section). When this happens you can click Data button and then select Notifications option, which will display all notifications. If you press on notification, it will be dismissed on pump, and pump will stop beeping/vibrating every few minutes.

    Most of notifications (alerts) are just of informational value, but Alarms and some other notifications will prevent pump commands. So for example if you are in Alarm state (and you don't confirm the Alarm), you won't be able to Stop/Start the pump or do any Canula/Reservoir actions. So confirming notification on Mobi is important step.

    Events

    AAPS is connected to pump 24/7. Main reason for this are events (which are at this moment not working correctly, but issue is being investigated - on pumpX2 library level), which give real-time warnings, notifications and information from pump.

    Refresh data in driver

    To keep driver working correctly, we have to refresh data regularly, so this are refresh operations.
  • Pump Status, Alerts, Alarms, History - This is refreshed every 5 minutes
  • Remaining insulin - Refreshed every hour (when over 50%), every half hour (when over 20%) or every 15 minutes when lower than 20%.
  • Battery Level - Refreshed every hour (when over 30%), every half hour (when over 20%) or every 15 minutes when lower than 20%.

    • Bolus

    Mobi driver supports both standard and SMB bolus types. When bolus is runing you will see dialog, but please note that progress of delivery is just an estimate (mobi delivery doesn't track how much of bolus was actualy delivered, we estimate the value with amount of time bolus was delivering), which means that bolus might finish before progress bar reached the end, or end is reached and bolus is still delivering...

    History

    Pump history is retrieved every 5 minutes, together with Pump Status check. History is always read from latest to oldest. We retrieve maximal 5 chunks of history data, each containing 200 records. Once we reach 1.5 months, we don't retrive any more historical data.

    So in the begining history will read lot of items, but afterwards, only new items will be read. Historical data is also cleaned from database, so we always have just last 1.5 months, so database won't grow needlesly...

    History is not parsed, we just display whatever history fields we have recognized by pumpX2 library. In some cases we do some minor parsing of certain recognizable fields, but not many. This might be extended in future, but history is of information value only and is not used by driver.

    You can see details of item, by clicking/pressing on them.

    Items can be filtered by Group, default option, displays all item, except Unknown items.





    Settings / Actions

    Settings and Actions
  • Opening the Settings page gives you a list of possible actions. You can access this page from the T:MOBI Overview. All the instructions in this section will start from this page.

    • Starting or Stopping the Pump
  • To resume insulin, select "Start Insulin", then "Resume Insulin" on the dialogue popup
  • To stop insulin, select "Stop Insulin", then "Stop Insulin" on the dialogue popup
  • If there is TBR running, you can't stop insulin. If TBR is running extra option will be displayed. Clicking it will stop TBR.

    • Pump Info
    This window just displays basic information about pump. This is mostly technical information, which might be needed if you had to contact Tandem support about a problem. Please don't mention that you are using AAPS or else they might be less than helpful... While using AAPS is not against the rules, it is frowned upon (they want you to use their original software - which is not existent (on Android) at the time of writing of this document).


    Starting / Stopping Pump / Cartridge - Cannula Actions (Solution with AAPS)

    Follow the instructions below for starting/stopping your pump, changing the cartridge, and filling the tubing or cannula.

    Changing Cartridge
  • Select "Cartridge/Cannula Setup"
  • Select "Change Cartridge", then "Begin Change Cartridge" on the dialogue popup
  • The cartridge on the pump will unlock, and you can remove the old and insert the new cartridge
  • Once inserted, you can now fill the tubing

    • Fill Tubing
  • Select "Cartridge/Cannula Setup"
  • Select "Fill Tubing". Disconnect the pump site from your body/site before filling
  • When ready to fill, select "Begin Fill Tubing" on the dialog popup
  • On your pump, hold down the pump button until insulin comes of the tubing
  • When done, a new popup will prompt you to continue. Select "Complete Fill" when done
  • The pump will finish up and you can now select "Done"

    • Fill Cannula
  • Select "Cartridge/Cannula Setup"
  • Select "Fill Cannula"
  • Enter the amount of units and press "Fill Cannula"

    Currently implemented functionalities

    • Get/Set Settings (disable IQControl, max bolus, max basal)
    • Get Battery Status
    • Get Insulin Level
    • Get/Set Basal Profile (Note: Mobi supports only 16 time segments, so you have to model your Basal Profile accordingly)
    • Get/Set/Cancel TBR (this enables Looping with oref0)
    • Get/Set Bolus (this enables Looping with oref1)
    • TZ and Daylightsaving time change (not tested)
    • Qualifying Events: On certain actions, pump sends so called QEs. You can see events in Data -> Events.
    • Alerts and Alarms: We read this on every pump status update (every 5 minutes) and display it in Data -> Notifications.

    Troubleshooting

    I forgot to charge up my pump and now it has powered down

    No panic. Just charge the pump for about 15 minutes or so and then bring pump out of sleep mode. Start AAPS and pump should be running. You will have to change the reservoir and then "Start Insulin". If there are any notifications you need to clear them first.
